* Scope
Recover the real recursive constraint benchmark without weakening its planner,
execution, budget, recursion, or trusted verification contracts. The live failure
has moved past planner parsing and validation: a valid typed planner object is
being exposed to the benchmark final-output path where the executed assignment
must appear.

* Required invariant
Planner structure is not task output. A validated plan must execute through the
closed interpreter, and only the materialized value of its terminal =final/1=
operation may become completion final output. Failed or absent final execution
must remain a structural failure; planner text/data must never be a fallback
answer.

* Initial evidence
Exact PR head =52ca5ef8...= passes deterministic/runtime/package checks but its
REAL OpenRouter and Paid OpenRouter depth 0/1/2 lanes fail after
=plan_parsed: true= and =plan_validated: true=. Trusted verification receives a
dict with =steps= rather than the required assignment dict with =assignments=.

* TDD contract
Add a deterministic end-to-end regression with a valid typed plan whose planner
representation differs from the executed final value. Cover explicit final
materialization, recursive child output, planner/reasoning-channel separation,
native tool/model plan selection, repeated model calls, retry/repair, failed
final execution, and distinct planner/final trajectory evidence. First prove
whether the defect is runtime-global or benchmark-local.

* Design
Keep =rlm_plan= and =completion_finish= as the authoritative final-value path;
they already return the value materialized by the terminal =final/1= expression
and retain model responses/events separately. Change the completion wiring so the
compiled root-planner skill projection is used only for the root planner request,
not as system context for task/model operations executed by the validated plan.
The existing trusted =provider_context/2= wrapper remains available for callers
that intentionally project a provider context; this slice does not broaden its
authority or change the public result envelope.

This is preferred over parser/verifier changes because the planner JSON is valid
strategy data and the verifier correctly rejects its =steps= shape. It is also
preferred over filtering arbitrary skill text after compilation: a planner-only
instruction cannot safely be inferred from natural-language content. Execution
model requests must receive their task prompt and provider-owned request options,
while recursive state, budgets, capabilities, transitions, response ledgers, and
trajectory lineage remain owned by =rlm_plan=.

Failure behavior remains closed: no terminal =final/1= means
=missing_final=; an unresolved final expression or failed model/tool operation
returns a structured execution error; no planner representation is used as a
fallback. The deterministic regression will use a local OpenAI-compatible server
that returns a planner-shaped value when planner instructions leak and an
assignment-shaped value otherwise, then route the resulting completion through
the trusted CSP verifier.
