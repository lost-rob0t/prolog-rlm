* Design phase (ADADR D — authorized by research approval)

** Design analysis input

- Designated open research question answered from existing precedent
  (no new research needed): the =persist(File)= backends
  (=rlm_artifact_persist.pl=, =rlm_conversation_persist.pl=,
  =rlm_effect_persist.pl=) establish the repository's durable-store shape:
  =library(persistency)= typed =persistent/1= records, =db_attach(File,
  [sync(...)])=, single-writer mutex, =require_attached= structured errors,
  backend-neutral facade so storage can be replaced without changing
  callers. The =.kb= tree follows exactly this shape.
- Tree-sitter 0.20.8 verified surface constrains the C design (see Analyze).
- #96 admission/currentness/publication machinery is reused verbatim where
  possible rather than reinvented.

** Design

*Ownership and state boundaries*

- New C file =c/rlm_tree_sitter_query.c= (+ =internal.h= additions,
  registration in =rlm_tree_sitter.c=) owning two new blob types following
  the #94 idiom:
  - =rlm_ts_query_resource { TSQuery *query; rlm_ts_language_resource
    *language; bool open; }= — retains the language resource for the query
    lifetime; immutable after compile, so usable from any thread; explicit
    close is idempotent; blob release drops the language ref.
  - =rlm_ts_query_cursor_resource { TSQueryCursor *cursor; int
    owner_thread; bool open; }= — thread-affine like parser/tree (cursors
    are mutable).
- New Prolog module =prolog/rlm_project_query.pl= — sibling of
  =rlm_project_syntax=, owning pack registry, compile cache, extraction
  generations, publication, currentness. Uses its own
  =rlm_project_query= mutex under the established lock order
  (source-registry mutex → project-query mutex), reusing
  =project_source_registry_valid=.
- New Prolog module =prolog/rlm_project_query_persist.pl= — persistency
  backend mirroring =rlm_artifact_persist.pl=: =persistent
  extraction_record(project, extraction, record)= and =persistent
  match_record(project, extraction, sequence, match)=;
  =db_attach(File, [sync(always)])= — =sync(always)= instead of the
  artifact backend's =sync(close)= because published extractions must
  survive =kill -9= (acceptance fixture), and extraction volume is
  bounded; single-writer mutex; =require_attached= structured errors.

*.kb tree layout (designated research question — answered)*

- Root: =<$PROJECT_ROOT>/.kb/project-query/<ProjectId>.pl= — one journal per
  project. =$PROJECT_ROOT= is trusted host configuration (registry project
  meta or explicit option); the runtime never guesses a filesystem root.
- Unresolvable root or read-only target ⇒ structured
  =project_query_error{kind:kb_unwritable}= — never silent memory-only
  degradation. Reload = =db_attach= replay on open (deterministic journal
  semantics from library(persistency)).
- The layout is backend-neutral: callers see the =rlm_project_query=
  facade; a future store implementation replaces the persist module only.

*FFI surface (rlm_tree_sitter.pl additions, all $-prefixed C internals)*

- =ts_query_compile(+Language, +Source, -Query)= — Source strictly
  atom/string; a callable raises a data-type error (acceptance criterion).
  On =ts_query_new=NULL: =tree_sitter_error(query_compile(Kind, ByteOffset),
  _)= with Kind ∈ =syntax=, =node_type=, =field=, =capture=, =structure=,
  =language= mapped from =TSQueryError=. Point (row/column) is derived in
  Prolog from the query source text (byte offset → UTF-8 line/column).
- Metadata: =ts_query_pattern_count/2=, =ts_query_capture_count/2=,
  =ts_query_capture_name/3=, =ts_query_capture_quantifier/4=,
  =ts_query_string_value/3=, =ts_query_predicates/3= (0.20.8-verified
  functions only).
- Execution: =ts_query_cursor_create/1=, =ts_query_cursor_exec/3=,
  =ts_query_cursor_set_byte_range/3=, =ts_query_cursor_set_point_range/3=,
  =ts_query_cursor_set_match_limit/2=,
  =ts_query_did_exceed_match_limit/1=, =ts_query_next_match/2=,
  =ts_query_next_capture/3=, =ts_query_cursor_close/2=.
- Matches project as =ts_match(Id, PatternIndex, [ts_capture(CaptureId,
  Node), ...])= — the native =TSQueryMatch.captures= array order and
  multiplicity preserved; repeated capture names stay distinct ordered
  entries.
- C =next_match=/=next_capture= loops call =PL_handle_signals()= between
  steps (chunked-input pattern from =rlm_tree_sitter_parser.c=) so
  cancellation interrupts cleanly; per-step granularity is the documented
  guarantee boundary (no native 0.20.8 query timeout).
- Compile cache: per-registry, keyed =(Language, GrammarRef,
  QuerySourceSHA256)=, max 32 entries FIFO eviction, process-lifetime only
  (recompilation after restart is deterministic; nothing native persists).

*Project layer API (rlm_project_query.pl)*

- Inert registration: =project_query_pack_register(+Registry, +Language,
  +Purpose, +QuerySource, +Meta, -Outcome)= — strict entry validation and
  structured faults mirroring =rlm_project_grammar_pack=; stores closed
  data =query_pack{identity, language, purpose, source, sha256,
  version, provenance}=.
- Trusted activation: =project_query_pack_activate(+Registry, +Language,
  +Purpose, -Outcome)= / =_deactivate= — mirrors =ts_grammar_activate=;
  registration never grants execution of anything.
- Extraction (canonical async direction, per #96):
  =project_query_extract_async(+Registry, +File, +Source, +Purposes,
  +Options, -Future)=, =_execute=, and synchronous =_await= facade. The
  execute path:
  1. reserve extraction generation (admission under mutex, pending state),
  2. validate source hash; *generation reuse only when provably the same
     generation* — the latest admitted parse for File is =current=, its
     content hash equals the supplied source, and it is the latest
     generation; otherwise run a fresh bounded =project_source_tree_parse=
     opening a new parse generation,
  3. reject predicate-bearing packs structurally
     (=unsupported_predicate=) via =ts_query_predicates=,
  4. compile (cache hit or =ts_query_compile=), compile-language vs
     tree-language mismatch = query_language_mismatch structured failure,
  5. cursor exec on root (or bounded: =byte_range=, =point_range=, or
     =subtree(Node)= where Node belongs to the same parse generation and
     maps to its native node via child-index path),
  6. iterate =ts_query_next_match= with between-step deadline checks
     (=timeout_seconds=, default 30.0) and =max_matches=/=max_captures=
     bounds (defaults 10000/50000),
  7. project captured nodes to closed =syntax_node(Parse, Path)=
     identities by parent-walk child-index paths (no full CST
     materialization), publishing captured-node facts with spans,
  8. publish match records + extraction record atomically under the
     lock order; close tree in =setup_call_cleanup/3=; persist journal
     append (=sync(always)=) before the =ok= ack.
- Extraction record (provenance, all 8 required fields):
  =project_query_extraction{extraction: query_extraction(File, Generation),
  parse, project, file, language, backend, grammar_ref (identity +
  version), pack_identity, pack_sha256, query_source_sha256, purposes,
  parse_generation, status: complete|partial, reason, currentness,
  provenance}= — pack re-registration with changed content hash yields a
  *new extraction generation*; prior facts go =stale=, never silently
  current (same admission/currentness machinery shape as #96).
- Queries: =project_query_current_extraction/3=,
  =project_query_matches/3=, =project_query_captures/3= (match-grouped
  primary view; capture stream secondary), =project_query_node_provenance/3=
  (joins capture → #96 node provenance + extraction provenance),
  =project_query_registry_clear/1=.

*Invariants (unchanged from research, restated as test obligations)*

- Query source is data with exactly one trusted sink
  (=$ts_query_compile= → =ts_query_new=); never callables/directives.
- Captures project through #96 closed identities; no pointer in any
  published fact.
- Packs: inert registration, explicit trusted activation, no authority or
  capability widening; no pack loads, downloads, or consults anything.
- Provenance completeness is re-proven by the Prolog verification gates at
  realization.

* Adversarial review (pre-realization pass on this design)

- Publication/destruction races: registry destroy during in-flight
  extraction must not republish orphans — #96 lock order reused;
  persistency appends only for valid registries. Kill order in
  =setup_call_cleanup= closes tree before journal ack on failure paths.
- Stale pack provenance after reload: pack identity is content hash, not
  path; activation records provenance; replacement forces new extraction
  generation. Risk accepted: old *compiled cache* entries keyed by old
  hash become unreachable (FIFO eviction bounds them).
- Wrong-grammar application: query-language vs tree-language resource
  mismatch rejected before exec (structured, not crash).
- Malformed/adversarial query text: =ts_query_new=NULL → structured
  compile error with byte+derived point+kind; fuzz-style fixtures
  (random bytes, truncated S-expressions, huge captures) must not crash
  and must not evaluate Prolog.
- Repeated capture names: ordered-list match representation; test with
  two same-name captures in one match asserts both entries survive.
- Zero/nested/multi-capture matches: match grouping preserved natively;
  nested captures assert parent/child spans.
- Unicode: byte ranges authoritative; point columns verified as UTF-8
  byte offsets via multi-byte fixtures (operator-agreed).
- Partial generation + limits: exhaustion ⇒ =partial(Summary)= + explicit
  =reason=, facts remain queryable but never claim complete.
- Restart/process-boundary: =sync(always)= journal; kill -9 fixture;
  compiled queries are NOT persisted (deterministic recompile) — no
  fresh-process native-pointer semantics exist.
- Cancellation mid-scan: deadline checks between steps + C-level
  =PL_handle_signals=; documented per-step granularity boundary; outcome
  =error(timeout)= like #96, admission left in pending→rejected state so
  no stale resurrection.
- Predicate-bearing packs: rejected structurally; Prolog-side evaluator is
  an explicit follow-up (research Inference 4).
- =ts_query_cursor_remove_match=: omitted from minimum surface unless a
  test requires it (research open question 2 default).
