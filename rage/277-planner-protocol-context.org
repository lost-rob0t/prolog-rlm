* Root decision closure (issue #279)
The forced-planner protocol regression: every =rlm_completion/4= request had
to produce a typed plan even when no runtime operation added value, so plain
questions paid a second model call that only echoed the goal, and the paid
=harness_guided_depth_2= case lost its final textual output inside that
second hop (=no textual final model output=).  The benchmark additionally
hardcoded =plan_parsed:true= / =plan_validated:true= for every successful
case, hiding which root decision actually ran.

Design: the root model chooses one closed JSON root decision.  The strict
direct envelope ={"mode":"direct","answer":"<nonempty final text>"}= finishes
immediately with exactly one model call, =plan:none=, empty transitions and
bindings, zero recursion, and truthful usage/trajectory data.  A valid typed
plan always wins over the envelope fallback, so plan semantics for context,
tools, model steps, and recursion are unchanged.  Envelopes with unapproved
fields, non-=direct= modes, or nontextual/empty answers fail explicitly as
=invalid_root_decision=; prose and native provider tool calls are never
accepted as either root decision form.  The prompt, the mandatory
=rlm-operate= skill, and planner repair diagnostics state both forms and
prefer direct completion when runtime operations add no value.  Repair
diagnostics remain bounded and never echo rejected provider output.  The
deep-experiment report records the actual =root_decision= and claims
=plan_parsed= / =plan_validated= only when a plan actually executed.

Live CI at the first fixed head exposed a second, related protocol gap: the
model reliably executed =context(slice)= plus all three =project_read=
reads but then composed the final as a one-hop field reference over the tool
binding (e.g. =field(var(readme),content)=), missing the envelope =value=
hop, and died unrecoverably at execution.  Root-plan validation now adds one
registry-aware structural rule: a first-hop field key outside the closed
=tool_result= envelope over a registry-tool binding can never resolve and is
rejected at validation with a =tool_result_envelope_field(Key,Bind)= repair
hint, so the existing bounded retry loop corrects it.  Direct trusted host
tools are exempt (host-defined result shape).  The live acceptance
assertions inspect bound values and transitions without over-constraining
model bind naming.

* Native direct-loop iteration
The earlier root-decision design treated =direct= as one strict answer envelope
with no runtime operations.  That remains a compatibility behavior of
=rlm_completion/4=, but it is not the ordinary direct agent strategy required
by the library.  Direct mode instead means a provider-native conversation loop
whose model may select bounded context and registered tools without producing a
typed plan.  Typed-plan mode remains an independent first-class strategy.  Its
current =model= operation is a bounded single provider call; the missing common
native-session integration is a gap to close, not deprecation or compatibility
baggage.

** Design
The decision-ready contract is recorded in =docs/direct-runtime.md=.  Add
=rlm_direct/4=, =rlm_direct_async/4=, and the canonical
=rlm_direct_execute/4=.  Add provider-neutral closed native schema, call,
result, and correlated message normalization.  Compiler-selected registry
schemas and capability-filtered context schemas are provider-visible data only;
all registered execution re-enters =tool_invoke_execute/6= and all context
execution reuses the existing bounded context operations.  The loop runs inside
one existing async worker, charges the completion budget across every turn and
observation, and preserves provider call IDs only as correlation.

Malformed batches are fully normalized before any member executes.  Duplicate
call IDs, unavailable schema names, malformed/non-ground arguments, denied
capability/authority, confinement failure, exhausted budgets, oversized
observations, cancellation, unsupported formats, and missing final text are
terminal structured failures.  A replayed or unresolved non-read operation is
not model retry authority: the durable boundary prevents resubmission and the
direct loop terminates conservatively.

Optional Frozen-Spec composition belongs above both strategies.  A closed
=direct | typed_plan= strategy remains bound to one exact Spec reference;
trusted graph handlers execute the existing branch runtime, refresh and observe
state, verify with =rlm_verify=, and optionally repair under one bounded graph.
Verification rejection never authorizes implicit effect replay.

* First-class typed-plan model steps
The typed-plan =model= operation still made one raw provider call without
native schemas while direct mode and root completion used provider-native
sessions. Typed plans are first-class, so this was an integration gap to close,
not deprecation or compatibility baggage. The plan runtime now accepts a
trusted =model_step_handler= runtime option, and both root completion and
direct =typed_plan_execute= supply a module-qualified =rlm_direct_model_step/10
= closure bound to the already-acquired context handle, the exact provider,
capabilities, the cancellation token, and the remaining budget (outer spent
usage already netted out).

** Design
The child model session is the existing direct loop entered through
=rlm_direct_execute/4= from inside the bounded worker: no second scheduler, no
nested Future wait, and no duplicate native loop. It re-runs canonical
query-aware prompt/compiler selection on the step prompt, projects
provider-native schemas that stay unchanged across continuation turns, and
preserves exact assistant/tool call IDs through correlated =role:tool=
messages. The plan reserves one step and one model call, then charges the
reported native execution atomically against the shared plan budget:
=iterations-1= steps, =model_calls-1= model calls, all tool calls and context
operations, and provider-facing observation bytes. The final response and every
provider response are recorded into the plan result; partial failures retain
every completed response so usage accounting stays complete. Per-step request
options are preserved but model-supplied =messages=, =tools=, =tool_choice=,
and streaming controls are rejected before provider dispatch. Standalone
=plan_run/5= without a handler keeps the one-raw-call compatibility path, and
=llm_query/3= is untouched. Handlers are trusted host closures and are never
carried in or constructed from model-controlled data.
