* Analyze
- The #94 FFI already parses and traverses arbitrary Tree-sitter grammars, but
  exposes only native, thread-affine handles.
- The #95 registry owns Project/File/Language identity and active grammar
  provenance, but intentionally has no persistent syntax observations.
- Native grammar handles must remain private to #95.  Materialized facts must
  survive native tree closure and must not expose pointer identity.
- Tree-sitter is suitable for structured text as well as programming languages;
  parser availability remains explicit trusted host configuration.

* Design
- Add =rlm_project_syntax= as a distinct epistemic observation store keyed by
  the existing source registry, File identity, and monotonically increasing
  parse generation.
- Add one trusted #95 parse operation that uses the active grammar internally
  and returns a temporary native tree plus closed parser provenance.  The syntax
  layer always closes the tree after projection.
- Identify parses and nodes with closed Prolog terms.  Node ordinals are stable
  only inside one parse generation; no cross-generation identity is promised.
- Materialize named-only or all-node projections with explicit source-byte,
  node-count, and depth limits.  Exhaustion publishes an explicit partial
  generation, never a complete claim.
- Retain source text once per parse generation.  Node text reads slice by UTF-8
  byte range, enforce caller byte limits, and reject stale generations unless
  historical access is explicit.
- Keep language/grammar installation data-driven.  Built-in extension evidence
  covers the requested common document/code formats; any host-registered
  Tree-sitter grammar continues through the same generic API.

* Adversarial review
- Closing a native tree must not invalidate materialized observations.
- Two files and two generations must not collide even when syntax is identical.
- Named-only projection must not allocate identities for punctuation tokens.
- A changed source digest must make the old generation stale before the new one
  is published current.
- Limits, excluded/generated/vendor policy, unavailable grammars, malformed
  source, Unicode byte offsets, and registry destruction need structured states
  and deterministic tests.
- Grammar registration remains inert data; no source, grammar, or project file
  is auto-loaded, consulted, downloaded, or granted authority by this slice.
