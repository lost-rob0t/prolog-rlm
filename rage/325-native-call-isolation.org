* Analyze
The established #313/#316 invariant is already correct after native wire
normalization: one side-effect-free classification pass retains trusted
bindings, evaluates duplicate-ID/effect/budget invariants against the original
request, then turns only an explicit phase+kind allowlist into per-call repair
observations. The gap is earlier. Wire normalization currently combines two
semantically different jobs:

1. validating the batch and each call envelope/identity;
2. parsing each call's argument object.

Envelope/identity corruption is not safely attributable and must remain
batch-fatal. An argument parse fault is attributable once the envelope, call
ID, type, and tool name have all normalized. Discarding that identity at the
batch =maplist/3= boundary prevents the existing trusted-binding and effect
isolation logic from deciding safely.

* Design
Keep the existing strict =native_tool_call_normalize/2= and
=native_tool_calls_normalize/2= public behavior. Add one additive batch
classification API in =rlm_native_tool= that shares the canonical envelope and
argument normalizers but returns an ordered entry per attributable call:

- a normalized call when arguments parse as one ground JSON object;
- a normalization-fault entry containing the normalized call identity, the
  bounded =normalize/malformed_arguments= cause, and the original closed wire
  call for exact assistant-message integrity comparison.

Every other wire fault remains terminal. The new API still validates the full
list and rejects duplicate IDs across valid and faulted entries before direct
classification.

=rlm_direct= consumes those ordered entries for both the response envelope and
the normalized assistant message. It extracts the original requested call
identities, resolves each malformed-argument entry once against the trusted
bindings, retains any resolved binding for original-request effect isolation,
and converts only =normalize/malformed_arguments= through the existing positive
recoverability policy. Valid entries follow the unchanged schema-validation
and execution path. Fault entries never acquire executable arguments and can
only produce the existing bounded =native_call_rejected= observation.

Acceptance criteria:

- valid read-only siblings execute exactly once in either order;
- the raw malformed call receives one ordered bounded
  =malformed_arguments= observation and the model can finish on the next turn;
- accounting reports one context call, zero tool calls, and two model turns;
- malformed envelope/ID/type/name, duplicate IDs, assistant mismatch,
  cancellation, and non-whitelisted normalization faults remain batch-fatal;
- a malformed raw call resolving to an effectful binding beside any sibling is
  batch-fatal before either handler executes;
- existing strict normalization callers and results are unchanged.

* Adversarial review
- Do not catch arbitrary per-call normalization failures. Recovery is limited
  to the exact =normalize/malformed_arguments= pair after identity validation.
- Do not insert an empty argument object and run normal validation: a faulted
  call has no execution path.
- Resolve the name only to recover trusted effect metadata. Capability,
  authority, confinement, and handler data are neither inferred from wire data
  nor exposed in the repair observation.
- Preserve the original wire call inside the internal classification entry so
  a response/assistant mismatch cannot collapse merely because two different
  malformed payloads share an ID and name.
- Run duplicate-ID and original-request effect checks across faulted entries;
  per-call recovery cannot shrink an unsafe batch.
- Reuse the existing direct loop, scheduler, budgets, cancellation boundary,
  observation renderer, and call ordering. Add no second executor or retry
  mechanism.

* Realize
=rlm_native_tool= now shares one envelope parser between the strict normalizer
and a new additive =native_tool_calls_classify/2= API. The latter retains only
an attributable =normalize/malformed_arguments= failure as an inert ordered
entry; strict normalization behavior and all other batch-fatal faults are
unchanged.

=rlm_direct= consumes the ordered entries for both response and assistant
validation. A normalization-fault entry is resolved once only to retain trusted
effect metadata, then passes through the explicit phase+kind recoverability
policy. It has no arguments field and therefore no execution path. Existing
classification, original-request effect isolation, budgets, cancellation,
ordering, observation rendering, and continuation remain canonical.
