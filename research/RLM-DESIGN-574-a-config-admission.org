* Scope

Design for issue #574 slices 1 (configuration_and_cli) and 2
(shared_cost_request_and_spend_rate_admission), per the approved research
record and the repository invariants: rlm_async is the only scheduler;
authority tiers exactly approve_diff < allow_once < allow_session < dangerous;
configuration may narrow authority but never bypass trusted policy; fail
closed on unknown/invalid options rather than clamping.

** Config file format (Prolog data, never consult/1)

Exactly one ground term read with read_term/3:

#+begin_example
swarm_config(1, [ cap_usd(0.10), n(4), min_agents(2), max_agents(8),

Non-ground terms, a second term, or unknown fields fail closed.

** Flag semantics

| Flag | Validator | Default | Notes |
|---|---|---|---|
| -c | cli_nonnegative_number_arg/2 | 0.10 | 0 valid: no further spend admitted |
| -n | positive integer | required | min_agents =< n =< max_agents |
| --min-agents/--max-agents | positive integers | 1 / 64 | min > max fails |
| --rate | positive integer | 60 | requests/minute |
| --spend-rate | swarm_spend_rate_parse/2 | none | windows min 1/60/1440/10080/525600; repeated flags accumulate one quota per window; duplicate window within layer last-wins, across layers strictest (min USD) wins |
| --kb | text path | none | type-validated only; existence checked by slice 6 |
| --enable-gaurdrail | bare (= all) or class list | none | validated against swarm_guardrail_class/1 |
| --enable-guardrail | alias | — | corrected spelling accepted; documented, not hidden |
| --web | boolean | false | bind/port is follow-on parity scope |
| --console | text path | none | follow-on parity scope; validated here |
| --backround/--background | boolean | false | alias pair, one option key |
| --deamon/--daemon | boolean | false | alias pair, one option key |

Unknown flags fail like rlm_cli.pl cli_fault(unknown_option(Arg)).

** Merge-vs-replace and precedence

- Scalars: last occurrence wins within a layer; CLI replaces file replaces
  defaults; provenance records cli(occurrence_index) so last-wins is
  observable.
- Collections (enable_guardrail): within CLI layer repeated flags merge;
  across layers the sets union (most restrictive wins) — guardrail
  enablement is a restriction and must never be silently reduced.
- Quota windows (spend_rate): across layers strictest wins per window.
- swarm_config_normalize/4 returns per-field provenance
  source(default | file(Path,TermPos) | cli(ArgIndex)) and derived
  effective bounds. Contradictions fail closed:
  swarm_config_fault(contradictory_bounds(min_agents,Max,Min)),
  swarm_config_fault(n_outside_bounds(N,Min,Max)),
  swarm_config_fault(unsupported_schema_version(Got,1)).
- swarm_config_redact/2 strips provenance detail and credential-bearing
  values; JSON emission reuses the rlm_trace envelope (trace_envelope/4,
  trace_json/2) — no second JSON writer.
- The swarm_config{} dict is the ONLY configuration value consumed by both
  library and pswarm. rlm_cli's completion_budget_from_options/2 keeps
  serving direct/rlm commands and is not reused for the swarm cap.

** State ownership

Pure function of (defaults, file term, argv) — no dynamic predicates. Config
is replayable and hashable so slice 11 restart can recompute it. The config
file is operator-owned; effective config is not persisted in slice 1.

** Invariants and failure behavior

- Fail on unknown/invalid, never clamp: unknown config field, unknown schema
  version, unknown guardrail class, unknown spend-rate unit, non-ground or
  multiple config terms, min > max, -n outside bounds, malformed spend-rate.
- The -c default 0.10 lives only in swarm_config_default/1 and never reads
  rlm_cli's default_cli_options/1 (max_cost_usd 0.25) — research amendment
  #4.
- One normalizer, one effective-config dict, two consumers.

* Slice 2 — shared cost, request and spend-rate admission

** Module

prolog/rlm_swarm_ledger.pl — the one atomic shared ledger (pure accounting;
no execution, no scheduling):

#+begin_example
swarm_ledger_open/3, swarm_ledger_close/1
swarm_ledger_reserve/4     % ok(reservation{...}) | error(admission_error{gate,...})
swarm_ledger_settle/3      % actual usage; never clamps actual to estimate
swarm_ledger_release/2     % failed/cancelled/never-executed work
swarm_ledger_extend/3      % retry growth, re-checks all gates
swarm_ledger_narrow_limits/3  % lower limits mid-flight
swarm_ledger_status/2      % snapshot incl. over_capacity flag
#+end_example

Subject is a closed compound
swarm_subject{kind:supervisor|child|retry|verification|guardrail, id,
attempt}. Options to swarm_ledger_open/3 include clock(:Goal) so rate-window
tests are deterministic without sleeps.

prolog/rlm_swarm_ledger_persist.pl — durable journal on the exact
rlm_conversation_persist.pl pattern (library(persistency), module mutex,
db_attach(File,[sync(close)])):

#+begin_example
:- persistent
    swarm_spend_record(serial, at, subject, kind:settled|unknown|overdrawn, usd),
    swarm_reservation_record(serial, at, subject, state:open|settled|released|extended, usd),
    swarm_request_record(at, subject),
    swarm_limit_record(at, cap_usd, rate_per_minute, spend_rates).
#+end_example

** Coverage without a second accounting system

Every model-call path already accumulates usage into the single
usage_summary shape via usage_add/3 (rlm_completion.pl, rlm_chain_runtime.pl,
rlm_direct.pl) and checks via budget_usage_check/3. The swarm layer composes
reserve → call the existing public API → settle from Result.usage. The
per-run budget (default 0.25) stays a separate independent boundary. The
admission contract: no model request proceeds without a reservation whose
subject names its kind; children reserve at spawn (slice 7), retries reserve
a fresh attempt serial, verification/guardrail runs reserve under their own
kinds.

** Atomic admission

swarm_ledger_reserve/4 does read-spend → all-gate check → reservation assert
inside one with_mutex critical section:

#+begin_example
committed   = Σ settled usd (journal)
outstanding = Σ open-reservation estimates
admit iff committed + outstanding + Estimate <= cap            (lifetime -c)
     and requests-in-rolling-minute < rate                     (--rate)
     and forall quota: Σ settled usd in window < quota usd     (--spend-rate)
#+end_example

Any gate failure returns a structured
error(admission_error{gate:lifetime_cap|request_rate|spend_rate, used, limit,
subject}) — admission denial is a runtime outcome, not a throw.

** Settle semantics

Always records actual usage cost; returns ok or overdrawn{delta} when actual
exceeds the reservation — actual spend is never clamped down, and settle
never fails because the cost is already incurred. Unknown cost charges the
reserved pessimistic estimate as kind:unknown, never 0.0.

** Lower limits must not erase

swarm_ledger_narrow_limits/3 appends a limit record and re-derives ceilings
only; committed spend, outstanding reservations and existing children/
evidence requirements are untouched. If the new cap is below
committed+outstanding, new admission denies until settle/release brings it
under, and status reports over_capacity:true. Mirrors the capabilities_
narrow/evidence_policy_narrow/rlm_authority_narrow family.

** Lock ordering and separation

Ledger mutex outer, persistency module mutex inner. The ledger never invokes
spawn/agent callbacks inside its critical section. All swarm execution
continues to route through rlm_async_submit — no thread primitives here.

** Rejected alternatives

- Settle-then-charge: concurrent in-flight calls collectively overspend;
  reserve-then-settle is the race-safe direction.
- Extending budget_usage_check/3 with cross-agent state: couples the
  canonical per-run path to swarm existence and risks the 0.25/0.10
  entanglement.
- Volatile reservations: crash would silently restore headroom; durable
  reservations are fail-closed.
- Per-path rate enforcement in provider call layers: three half-enforcements;
  one subject-addressed ledger at the swarm boundary is a single choke point.
