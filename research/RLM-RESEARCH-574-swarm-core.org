* Research Question

What verified substrate does the existing prolog-rlm runtime provide for the
requested =rlm_swarm= library and =pswarm= CLI, what is the current competitive
baseline for multi-agent swarms, and which bounded implementation slices are
coherent — without creating a second scheduler, agent loop, or runtime that
duplicates canonical prolog-rlm mechanics?

This record consolidates the research phase of issue #574. It does not propose
a novel feature; it maps the issue's required base-core collaboration surfaces
onto existing runtime modules and records the approval-relevant evidence.

** Scheduler invariant (confirmed, not inferred)

=rlm_async.pl= is the only general scheduler. Raw thread primitives occur
only in: =rlm_async.pl= (worker pool), =rlm_agent.pl= (bounded per-runtime
supervision pool + agent mailboxes), and =rlm_authority.pl= (one-slot
approval gate). All higher-level modules route through =rlm_async_submit=;
compatibility facades delegate only. Swarm work must compose with this, not
parallel it.

** Competitive baseline (dated, not a uniqueness claim)

Herdr's exposed behavior includes agent swarms with per-agent skills, session
state restore, plugin/socket APIs, and a core with command/security/schema
docs. Peer systems reviewed: CrewAI crews, LangGraph durable
execution/interrupts, OpenAI Agents guardrails, KEDA scaling policies,
OpenHands sandboxes, OpenTelemetry GenAI spans. Known contradiction: indexed
Pi-swarm snippets advertise an expiring board, wildcards and broadcast, while
the fetched README states there is no separate message store, no wildcards,
no broadcast. Recorded as uncertainty; snippets were rejected as evidence.
SwarmForge and Pi-Herdr versions are not pinned; their claims are not
load-bearing for any slice.

* Implementation Implications

The 12 proposed slices and their dependency graph remain exactly as recorded
in =.prolog/kb/swarm-project.pl= (=swarm_core_slice/2=,
=swarm_slice_dependency/2=): (1) configuration and CLI, (2) shared cost,
request and spend-rate admission, (3) scoped identity and discovery,
(4) peer and group messaging, (5) durable searchable message board,
(6) gated domain-extensible shared KB, (7) policy-gated peer and child
creation, (8) adaptive recursive delegation, (9) guardrails and host
authority integration, (10) task lifecycle and evidence-backed acceptance,
(11) durable service stop/drain/restart/resume, (12) conformance, failure
fixtures and packaging. Generic runtime support stays in prolog-rlm;
reusable canonical expert definitions remain dotfiles-owned under
=.zara/experts/=.

* Rejected Alternatives

- Second scheduler or one-thread-per-agent runtime: violates the repository
  invariant; =rlm_async= is the only scheduler.
- A separate rlm-swarm repository/fork consuming prolog-rlm: rejected by the
  user on 2026-11-13 in favor of in-repo development in the main repository.
- Treating worker claims, board posts and proposed KB assertions as trusted
  evidence: the issue explicitly forbids collapsing messages, posts,
  observations, policy and accepted knowledge into one interchangeable
  authority.
- Arbitrary =consult/1=-based KB loading for guardrails: executes host
  directives and breaks the trusted/inert distinction.
- Inferring novelty from search snippets: rejected because of the observed
  Pi-swarm snippet/README contradiction.

* Open Questions (approval amendments)

1. Pin SwarmForge and Pi-Herdr versions and re-fetch mutable peer docs
   (CrewAI, LangGraph) at design time before any comparative claim.
2. Resolve the Pi-swarm snippet/README contradiction in the competitive
   matrix with a dated note; keep snippets non-authoritative.
3. Leaf-expand the configuration/CLI coverage matrix (the current rows are
   setting families; ACC01 requires leaf-level registry expansion).
4. Resolve the default-cost mismatch: the requested swarm cap default is
   =-c 0.10= USD while =rlm_completion= defaults to 0.25; the design must
   keep these separate.
5. Integrate the result-acceptance gate into every supervised-child trace
   before slice 10 can claim evidence-backed acceptance.
6. A depth-aware recursive =rlm_subagent= binding does not exist and
   currently fails closed; slice 8 depends on designing it.
7. Full Herdr parity (desktop/mobile clients, web UI, AgentProlog console)
   remains required follow-on scope, not silently dropped and not yet sized.
